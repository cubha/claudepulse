## ST2 — 서브에이전트 수집 + 전역 dedup + 감시기 [TDD]
- 변경 파일: `src/services/WorkspaceMapper.ts`, `src/services/JsonlParser.ts`(`mergeRecordsAcrossFiles` export), `src/services/FileWatcher.ts`(`CLAUDE_WATCH_DEPTH`=3, `isIgnoredWatchPath`), `src/extension.ts`, `test/unit/subagentCollection.test.ts`(신규 16건)
- RED: 현행 동작 stub(`perFile.flat()`·depth 2·기존 ignore)으로 값 단위 RED 10건 확인. 추가로 내가 쓴 테스트 정규식 결함 1건(`[^)]*`가 `getConfig()` 괄호에서 끊김)을 수정했다 — 구현이 아니라 테스트 자체의 결함이다
- 구현 결정:
  - 겹치는 기록은 **메인 체인 원본 우선**으로 남긴다. 실측 겹침 약 45건이 전부 "부모=메인 / subagents=사이드체인" 조합이었다. 최신 우선이면 부모 비용이 서브에이전트로 재분류된다
  - 최상위 파일 판정은 기존대로 이름만 본다(`!isDirectory`, 심볼릭 링크 유지). subagents는 `isFile`만 본다
  - `.orphaned-*`/`.superseded-*` 파일은 최상위에 생기면 기존과 같이 수집되고, 전역 dedup이 중복을 막는다. 로컬에는 0개라 실파일로는 검증하지 못했다
- 실데이터:
  - 파일 810개(subagents 738개), 레코드 34,033 → 46,703건
  - 서브에이전트 비용 $695.57(9.8%), 서브에이전트 737개가 새로 집계된다
  - 메인 체인 비용은 $6,428.21로 이전과 동일하다(원본 보존 증거)
- 미확인 사항:
  - 초기 로드에서 파싱할 파일이 738개 늘었다. 증분 캐시는 mtime 기준이다. 실제 VS Code에서의 첫 로드 시간은 재지 않았다
  - 폴링 대상이 약 738개 늘었다(tool-results·meta.json 제외 후). WSL 폴링 부하는 재지 않았다
  - 워크스페이스 스코핑·브랜치 집계는 사이드체인 레코드의 `cwd`/`gitBranch`에 의존한다. 서브에이전트 기록에도 이 필드가 있는 것으로 보이지만, 집계 결과를 필드별로 대조하지는 않았다
