## ST2 — 사이드바 Codex 버킷 행 `(proj N% left)` 복원 [TDD]

- 변경 파일
  - `src/webview/codexBandBurn.ts` — `CodexBucketBurn.projText` 추가, `buildCodexBucketBurnRow`가 렌더
  - `test/unit/codexBandBurn.test.ts` — **신규 describe 2개(5건) append만**, 기존 단언 무수정(import 줄에 `buildCodexBucketBurnRow` 추가)
- 구현 결정
  - 게이트: `projText`는 `safeUntil`이 non-null일 때만 — `buildBurnRow`(webviewShared.ts)와 동일. 포맷도 동일: ` · {safe_until} {HH:MM:SS} ({proj} {N%} {left})`.
  - **대시보드 카드(`panelView.ts` updateCodexBandSection)에는 렌더하지 않았다** — 로드맵 원문 범위가 사이드바. 필드는 공유 struct에 있으므로 이후 대시보드 노출은 1줄 변경.
  - 파일 상단 낡은 주석("사이드바는 기존 buildBurnRow를 계속 쓴다") 정정 — v0.2.3부터 사실이 아니었다.
- 기존 단언 무수정 근거(acceptance-critic V2 — 파일이 untracked라 git 대조 불가): 이 세션의 편집은 (a) 2행 import에 `buildCodexBucketBurnRow` 추가 (b) 파일 말미 append 두 가지뿐이다. 기존 10건은 편집 전·후 모두 통과(편집 후 15 = 기존 10 + 신규 5).
- RED 기록: 신규 5건 중 4건 단언 실패(`projText` undefined · proj 조각 부재), 1건("소진 궤도 아니면 조각 없음")은 구현 전에도 통과(부정 단언이라 당연). 테스트 미수정 구현 → 15/15 GREEN.
- 미확인 사항
  - 소진 궤도에선 투영이 거의 항상 `0%`로 클램프된다(`calcProjAtReset`이 `max(0, …)`) — 즉 이 조각은 실질적으로 "(proj 0% left)"로만 나온다. Claude `buildBurnRow`도 같은 성질이라 규칙 일치를 우선했다. 정보가치 자체에 대한 판정은 이 SubTask 범위 밖.
