  - ESLint flat config는 구 규칙 4개를 그대로 옮겼다. 구 설정의 `parserOptions.project`(typed linting)는 버렸다. type-checked 규칙을 하나도 켜지 않아 쓰이지 않던 옵션이다. 새 recommended 세트에서 생긴 오류는 0건이었다.
  - `test:integration`: `@vscode/test-cli` + `.vscode-test.mjs`(mocha tdd) + `pretest:integration`(esbuild CJS 번들) + `xvfb-run`. 스모크에 "기여 명령 전부 등록" 단언을 추가했다.

## ST1 — 비-assistant 이벤트 채널 + SessionRecord 신규 필드

- 구현 결정
  - `ParseCache.events`는 **누적**이다. costSnapshots(last-wins)와 반대다. 잘림·교체로 전체 재파싱하면 새로 시작한다(중복 누적 방지, 테스트로 잠금).
  - API 오류 줄(429·5xx)은 assistant 줄이다. 이벤트로 뽑은 뒤 **기존 사용량 레코드 처리도 그대로 탄다**(`<synthetic>` 레코드 무행위변경, 테스트로 잠금).
  - `eventKey` = uuid. pr-link만 uuid가 없어 `pr:<repo>#<n>@<session>`을 쓴다. 파일 간 merge에서는 같은 키 중 **가장 이른** 기록을 남긴다(PR이 처음 연결된 시각).
  - `thinkingTokens`·`effort`·`cacheMiss`는 필드가 없으면 **미정의**다(0 아님). 집계가 "미상"과 "0"을 구분하게 하려는 것이다.
  - `effort`만 쓴다. `perTurnEffort`는 턴 오버라이드라 34k행이 null이다.
  - 실데이터 대조(1,001파일): 이벤트 turn 2,145 · hooks 2,140 · compact 114 · pr_link 223 · api_error 41. 캐시 미스 레코드는 490건으로 grep 실측(1,049)보다 적다. grep은 스트리밍 중복 줄을 세고, 파서는 requestId last-wins로 dedup하기 때문이다(마지막 엔트리에 필드가 항상 있음을 사전 실측으로 확인).
- 미확인 사항
  - `turn_duration`·`stop_hook_summary`의 `isSidechain=true` 사례는 30일 데이터에 0건이었다. 플래그는 싣되, 집계(ST8)가 사이드체인을 어떻게 다룰지는 실례가 없어 검증하지 못했다.

## ST2~ST8 — Claude 신호 (커밋: RED d8a6053 → GREEN)

- 구현 결정
  - ST2·ST4·ST5·ST6·ST8은 `src/services/signals/*.ts` 순수 함수다. ST3(thinking)·ST7(effort)은 집계기에 둔다. ST3은 today 스코프 공유를 위해, ST7은 귀속 카드 24h/7d/All 토글 공유를 위해(`computeAttribution`)다.
  - RED는 처음에 "모듈 없음"(import 오류 = 무효 RED)이었다. 시그니처만 가진 `throw 'not implemented'` 스텁으로 바꿔 유효 RED(22건)를 만든 뒤 커밋했다.
  - **ST2 캐시 미스**: 추정비용 = missed × (쓰기요율 − 읽기요율). 쓰기요율은 그 레코드의 5m/1h 생성 토큰 비율로 가중한다. 토큰 미기록 원인은 null이며 합계는 하한이다(`hasUnknownTokens`). Codex 레코드는 분모에서 뺀다.
  - **ST3 thinking**: 분모는 thinking 필드가 있는 레코드의 output만이다. 오늘 필드가 없으면 null.
  - **ST4 차단**: 에피소드 키 = (rateLimitType, resetsAt). 5xx는 별도, quota 없는 429는 `unclassified429`.
  - **ST5 PR**: 세션 단위 정확 조인(서브에이전트 레코드 포함). 다중 PR 세션은 `sharedSessionCount`로 표시하고, 레코드 없는 세션은 제외한다($0 PR 금지).
  - **ST7 effort**: 메인·사이드체인 모두 포함. 분모 = 스코프 총비용(미상 버킷 포함).
  - **ST8 명세 변경(구현 중, 테스트 동반 수정)**: 훅 비율 분모를 **벽시계 턴 합 → 턴 중앙값**으로 바꿨다(`hookShare = avgHookMsPerTurn / medianMs`). 실측 최장 턴이 33시간(승인 대기 포함 벽시계)이라 합이 이상치에 지배됐다. 30일 실측 기준 합계 대비 0.21%, 중앙값 기준 1.5%다.
    - ⚠️ 계획 단계에서 PLAN·사용자 보고에 쓴 "2.1%"는 최장값을 합계로 잘못 읽은 **오계산**이다. PLAN §2-3을 정정한다.
  - 훅 표시명은 경로 토큰을 basename으로 줄인다(`hookDisplayName`). 인터프리터는 떼고 인자는 최대 3개까지 둔다.
