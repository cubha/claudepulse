## ST4 — 집계 [TDD]
- 변경 파일: `src/types/index.ts`(`SessionRecord.attributionAgent`, `SubagentTypeUsage`, `SubagentTypeUnattributed`, `AttributionScope`·`UsageSummary` 필드), `src/services/JsonlParser.ts`(attributionAgent 보존 1줄), `src/services/UsageAggregator.ts`(`computeAttribution` 사이드체인 분기 안에서 타입별 누적), `test/unit/subagentTypeBreakdown.test.ts`(신규 8건)
- RED: 현행 동작 stub(빈 배열·0 버킷, 파서 미보존)으로 7건 값 단위 RED. 이 중 3건은 `[0].share` 접근 TypeError인데, 원인이 "빈 배열 = 구현 누락"이라 유효 RED로 판단했다(import·오타 아님). "서브에이전트 없으면 빈 목록" 1건은 stub과 같은 동작이라 처음부터 통과(특성 테스트)
- 실패 테스트 선커밋은 하지 않았다 — v0.2.5 ST1~3도 미커밋 상태로 진행해 작업트리 일관성을 유지(ship 시 단일 커밋)
- GREEN: 8/8
- 구현 결정:
  - 사이드체인 분기 안에서만 누적 → 메인 체인은 attributionAgent가 있어도 제외(테스트로 잠금)
  - share 분모 = `subagentCostUsd`(타입 합 + 미상 버킷과 동일 모집단)
  - runCount = 타입별 고유 agentId. agentId 없는 레코드는 실행 수에 안 잡힌다
  - 정렬: 비용 내림차순, 동률이면 토큰 내림차순(미가격 $0 타입끼리 순서 안정화)
- 실데이터(2026-09-29): 서브에이전트 $635.54 = 15개 타입 합 + 미상 $0 (정확히 일치). 상위: general-purpose $282.16(44.4%, 69회), fork $142.50(22.4%, 104회), acceptance-critic $61.95(128회). 미상 버킷은 runCount 12·토큰 0 → UI에서 숨김
- 미확인 사항:
  - `fork` 타입은 부모 이력 사본으로 시작한다. 겹치는 message.id는 v0.2.5 전역 dedup이 메인 원본을 남기므로 fork 비용에 부모 비용이 섞이지 않는다고 보지만, fork 단독으로 대조하진 않았다
  - 과거 CC 버전(부모 파일에 사이드체인 인라인 기록)의 레코드에는 attributionAgent가 없을 수 있다 → 미상 버킷으로 간다(의도). 30일 롤링 데이터에는 해당 표본이 없어 실관측은 못 했다
  - agentId 없는 사이드체인 레코드의 실재 여부 미확인(있으면 비용은 잡히고 실행 수만 누락)
