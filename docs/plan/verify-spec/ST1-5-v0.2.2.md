- **ST1** `panelView.ts buildPanelShell()` — `panel-daily-card`/`panel-longterm-card`/`panel-monthly-card` 3개 블록을 `panel-cost-period-card` 1개로 통합. 탭줄(`.cost-tab-row` 3버튼) + pane 3개(`cost-pane-daily|longterm|monthly`). **canvas/빈상태/note/readout id는 전부 원래 이름 그대로** — `updateDailyChart`/`updateLongTermSection`/`updateMonthlyChart` 본문은 **1줄도 바뀌지 않았다**(id로만 DOM을 찾기 때문).
- **ST2** 탭 상태 `costPeriodTab`(모듈 스코프) + `.cost-tab-btn` 핸들러 + `applyCostPeriodTab()`(active/aria-selected/pane display/readout display 동시 이동) + `updateCostPeriodSection()` 디스패처. `updateUsageSection()`이 3개를 직접 부르던 것을 디스패처 1회로 교체. `rebuildPanelDom()`에 `costPeriodTab = 'daily'` 리셋 추가.

## 구현 결정 (stub/하드코딩/보류 없음, 다만 아래 3건은 의도적 선택)
1. **숨은 pane에서 Chart를 만들지 않는다.** 대안(생성 후 `resize()`)은 Chart.js 내부 사이징 타이밍에 의존한다 — 대신 활성 탭 것만 그리고 전환 시점(컨테이너가 이미 보일 때) 처음 그린다. 대가: 비활성 탭의 readout/note가 전환 전까지 stale(화면에 안 보이는 값이라 무해, 전환 즉시 갱신).
2. **readout 3개를 헤더에 나란히 두고 표시만 전환.** 단일 readout으로 합치면 3개 update 함수가 같은 id에 쓰게 되어 렌더 로직을 고쳐야 한다 — 그러면 "무변경 보장"이 깨진다.
3. **카드 슬롯은 일별 카드 것을 승계.** `class="card "` 개수가 6으로 유지돼 기존 M2 회귀잠금의 측정 온전성이 살아 있다.

## 테스트 변경 보고 (정합성 가드 — 명세 변경 케이스)
`panelDesign.invariants.test.ts`를 **통과시키려고 약화한 것이 아니라** 명세가 바뀌어 갱신했다. 변경 내역:
- survivor 목록: `panel-daily-card` → `panel-cost-period-card` (카드 개수 6은 **불변**)
- stripped 목록: `panel-longterm-card`/`panel-monthly-card` 제거 — 두 id가 **소멸**했고 루프가 `idx > -1`을 단언하므로 남기면 "카드 클래스가 붙었다"가 아니라 "id가 없다"로 실패한다(허위 실패)
- **추가 단언(순증)**: 탭 3개·pane 3개·`data-period`/`cost-pane-*` 존재 · canvas 3종·빈상태 3종·readout 3종 전부 존치 · 옛 3개 id 소멸 · pane이 통합 카드 **안**에 위치. 즉 잠금이 "카드 6개"에서 "**셋을 하나로 접었고 아무 차트도 잃지 않았다**"로 강해졌다.
