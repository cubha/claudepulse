## ST7 — gifenc/pngjs 의존성 (R7)

- 구현 결정
  - ⚠️ **PLAN이 틀렸고 실측이 바로잡았다.** 계획은 "lockfile 재생성은 하지 않는다"였는데, `.github/workflows/publish.yml:37`이 `npm ci`를 쓴다 — `npm ci`는 package.json과 lock이 어긋나면 **하드 실패**한다. 재생성 안 하면 배포 워크플로가 깨진다.
  - 스크래치패드 복제본에서 영향 범위를 먼저 쟀다: lock diff는 **버전 필드 + 2개 엔트리**가 전부였고 전이 의존성 추가 0건. `npm ci --dry-run` 통과 확인.
  - `devDependencies`에 넣는 것이 이 repo의 관행과 일치한다 — `playwright-core`·`sharp`가 이미 같은 위치에 있다(둘 다 검증·캡처 도구).
  - `.vscodeignore`가 `node_modules/**`를 제외하므로 vsix 크기 영향 0.
- 미확인 사항
  - `npm install --package-lock-only`를 repo에서 직접 돌렸다. diff를 확인했고 예상과 일치했으나, npm 버전이 다른 환경에서 재실행하면 포맷이 달라질 수 있다.

## ST8 — 프로토타입 드리프트 (R8)

- 구현 결정
  - error 9 = **3규칙 × 3파일**이었다. `D-TYPE-07`·`D-TOKEN-01` 6건은 CLAUDE.md §9 / DESIGN-TOKENS §13.1이 **상시 잔존**으로 명시한 대상이라 손대지 않는다 — 0으로 스냅하면 정리가 아니라 왜곡이다.
  - 실위반은 `D-COLOR-02` 3건뿐: `#93C5FD`·`#FCD34D`. v0.1.56 이전 팔레트의 잔재 — **드리프트를 되돌린 것**이지 새 결정이 아니다.
  - ⚠️ **첫 시도는 틀렸고 실측이 잡았다.** 처음엔 `--c-sonnet`/`--c-warn`(솔리드 액센트)으로 치환했는데, 이 리터럴들은 **같은 hue의 틴트 배경 위 전경**으로 쓰인다 — 솔리드를 올리면 대비가 붕괴한다. 실측: `usage-heatmap .scope-toggle button.active`가 **2.96:1**(불투명 배경이라 합성 불필요, 유효 수치). design-lint의 대비 규칙 `D-COLOR-05/06`은 `--observed` 게이트 안이라 **이번에 돌지 않았고**, 그래서 error 6이라는 숫자는 이 문제에 대해 아무것도 말해 주지 않았다.
  - 올바른 토큰은 `--fg-sonnet`(#A3CEF9) / `--fg-warn`(#F7DA90) — styles.css가 정확히 "액센트 틴트 위 전경" 용도로 가진 것이다. 프로토타입 토큰 블록 3곳에 같은 값으로 선언 추가.
  - 알파 합성까지 한 대비 재측정(6개 셀렉터, 전/후): 전부 4.5:1 이상이며 **4건이 개선**됐다(`.st.ok` 7.70→8.43, `.scope-toggle` 6.04→**6.62**, `.tag.a` 6.38→6.99, `.st.alt` 8.46→8.93). 감소한 2건도 기준 위(`qp-badge--auto` 7.37→4.90, `sb-chip--warn` 9.21→8.27).
  - 결과: error **9 → 6**(기준선 복귀) · warn **29 유지**.
  - CLAUDE.md §9의 기준선 문구에 경위와 "`--c-*`가 아니라 `--fg-*`인 이유"를 병기했다.
- 미확인 사항
  - 대비는 계산으로 확인했고 **눈으로 보지는 않았다**. 4.5:1 통과가 "보기 좋다"를 뜻하진 않는다.
  - `D-COLOR-05/06`(대비)은 `--observed` 없이는 돌지 않는다. 이번엔 손으로 쟀지만, 게이트가 아니라서 **다음에 같은 실수를 하면 아무도 안 잡는다** — 별건 후보.

## ST9 — `.panel-root` 패딩 (R9)

- 구현 결정
  - **PLAN이 기록한 선행 충돌이 실측에서 성립하지 않았다.** 752px/1100px 양쪽에서 재 보았다:
    - 캘린더: `.calendar-grid-area`는 `overflow-x: auto`(v0.1.44 수정)라 폭이 줄면 **스크롤될 뿐 잘리지 않는다**. 752px에서는 패딩 변경 **이전에도 이미** 스크롤 중이었다(scrollWidth 756 > clientWidth 628 → 612). 1100px에서는 양쪽 다 스크롤 없음.
    - Y축 정렬: 모든 카드 left 32 → 40, 모든 캔버스 left +8. **상대 오프셋이 완전히 동일**하다(chart-cache-spark의 -4px 차이는 변경 전에도 있던 값).
    - 가로 페이지 스크롤: 양 폭 모두 없음.
  - 따라서 채택. `--sp-4` → `--sp-6`(16px → 24px).
- 미확인 사항
  - 700px 미만의 매우 좁은 패널은 재지 않았다. 좁을수록 캘린더 스크롤 구간이 길어지지만, 그건 패딩과 무관하게 이미 있던 동작이다.
