컨텍스트 사용률 · 세션 선택기 시안

문제: 멀티루트 워크스페이스에서 게이지가 항상 workspaceFolders[0] 하위 최신 레코드 1건만 보여줘, 실제 작업 중인 세션이 아닌 다른(비활성) 세션의 값이 뜨는 경우가 있었다. 해결: ① 후보 풀을 열린 폴더 전체로 확장(기본값 = 자동/최신) → ② 📁 워크스페이스 칩을 클릭하면 특정 세션을 고정(pin)할 수 있는 선택기 제공. 아래는 3단계 흐름과 그 결과로 사이드바가 어떻게 바뀌는지의 목업이다.

1

지금 — 클릭 불가, 스코프 불투명

칩은 정보 표시 전용이다. 어떤 세션이 왜 선택됐는지 알 방법이 없고, 사용자가 개입할 수단도 없다.

CLAUDEPULSE — 사이드바
컨텍스트 사용률 41% (≈82K/200K) ≈ 근사치
📁 APP-BE 🕐 1d 19h
실제로 APP-FE에서 작업 중이어도 이 값은 바뀌지 않는다 — 1d 19h 전 APP-BE 레코드가 박제된 상태. stale 스타일(opacity:.55)이 있긴 하지만 원인·대안을 알려주지 않는다.
2

칩 클릭 → 세션 선택기(QuickPick)

📁 칩이 클릭 가능해지고(호버 시 보더 강조 + 셰브런), 클릭하면 VS Code 네이티브 QuickPick으로 이 워크스페이스에서 관측된 세션 목록이 뜬다. 기본은 AUTO — 가장 최근 활동 세션이 표시 중임을 배지로 알린다.

3

고정(pin) 후 — 그리고 오래 조용해졌을 때

특정 세션을 고르면 칩이 📌 고정됨 상태로 바뀐다. 동시에 여러 세션을 오가며 작업할 때 값이 계속 튀는 걸 막는 용도다. 단, 고정한 세션이 4시간 넘게 조용해지면(오늘 겪은 것과 같은 상황) 경고 배지로 알리고 자동 모드로 되돌리는 링크를 바로 붙여, 오늘 같은 "박제된 값을 못 알아채는" 상황이 재발하지 않게 한다.

구현 메모 — 데이터 모델 변경 필요분

SessionSummary.lastActivity NEWQuickPick 정렬(최신순) 기준. 현재 startTime(첫 레코드)만 있어 "최근 활동순"을 못 만든다.
SessionSummary.model NEW목록 항목의 모델 배지/도트 색상용.
SessionSummary.contextTokens NEW목록 항목의 126K/200K (63%) 표기용 — 세션별 마지막 컨텍스트 점유량.
UsageAggregator.aggregate()후보 풀을 workspaceRoot 단일값 → workspaceRoots: string[](열린 폴더 전체)로 확장. 미고정 시 풀 내 최신 레코드 자동 선택(기존 로직 그대로, 풀만 확장).
고정 상태 저장context.workspaceState(창 단위) — sessionId pin. 세션이 없어지거나 workspaceRoots 밖으로 나가면 자동 해제.
Stale 임계기존 CONTEXT_STALE_THRESHOLD_MS(4h) 재사용 — 신규 상수 불필요.
